# 企画からYouTube公開まで

1. **誰に、何を分かってもらうか決める。** 初学者に一つの仕組みを伝えるなら、最初は3〜5分程度の範囲から始めます。
2. **根拠をそろえる。** 数値、制度、科学の説明は出典を調べ、事実・推測・比喩を分けます。
3. **掛け合いにする。** しょうがが説明、だいこんが素朴な質問、にんにくが条件や例外、とうがらしが確認問題を担当すると組み立てやすくなります。
4. **一つの台詞と一つの図を対応させる。** 図だけでも関係が分かるかを考えます。全部を字幕に頼らないことがポイントです。
5. **台本JSONを作る。** `prompts/`は任意の支援用です。AIを使わず手で編集しても動きます。
6. **`npm run stills` で絵コンテを確認する。** 項目数、文字の大きさ、色、キャラクターと字幕の重なりを確認します。
7. **自分の音声を配置する。** `npm run narration` → 録音/TTS → `audio/` の順です。
8. **短い範囲で試す。** `npm run render -- --seconds 10 --width 1280 --fps 24`。映像と声の同期、声量、BGMの聞き取りやすさを確認します。
9. **全編を書き出す。** `npm run render`。結果は `output/video.mp4` です。
10. **全編を試写して投稿する。** タイトル、説明文、出典、チャプター、字幕、サムネを用意し、自分のYouTube Studioからアップロードします。子ども向けか、AI使用の開示が必要かなどは動画の内容と最新のYouTubeルールに合わせて設定します。

## 確認リスト

- 人名・メール・APIキー・画面通知など、出したくないものが映っていない。
- 説明の出典があり、誤りや過度な断言がない。
- 冒頭で何が分かるか伝わり、原作記事を知らなくても理解できる。
- 小さなスマートフォン画面でも見出しと図が読める。
- 全員の声を聞き分けられ、BGMが声を邪魔しない。
- `--draft` の無音プレビューを完成版と取り違えていない。
- 素材・音楽の利用条件を満たしている。

APIによる投稿・クラウドへの自動アップロードは含みません。GitHubに完成動画を入れる必要もありません。
